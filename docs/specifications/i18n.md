# Languages (i18n)

Judge26 is used by the Swiss WRO association, so it ships in the national languages German,
French and Italian, plus English. Romansh is not supported. See
[ADR 0009](../architecture/decisions/0009-internationalization.md) for the decisions.

## Behaviour

- **Every build contains all four languages.** The messages are part of the source
  (`apps/web/src/i18n/locales/<language>/<module>.json`) and are compiled into the bundle by the
  build. Administrators cannot change or add translations at runtime; texts change with a release.
- **Each user picks their language** with the language menu in the header (each language is listed
  in itself: Deutsch, Français, Italiano, English). The choice applies immediately.
- **First visit:** the browser's preferred languages decide (`fr-CH` → French); English when none
  of them is supported.
- **The choice is remembered** on the device (`localStorage`, key `judge26.locale`) and, for
  signed-in users, on the account (`users.language`). Signing in applies the account's language; a
  user without one gets the language they are using, saved on the account. Registration saves the
  language the user registered in.
- **Links:** `?lang=de|fr|it|en` on any page selects that language, e.g. for a TV display
  (`/live/<id>/tv?lang=fr`).
- **Formats** follow the language with Swiss conventions (`de-CH`, `fr-CH`, `it-CH`, `en-CH`):
  dates, times and numbers (`1’234.5`). Times use the 24-hour clock.
- **Swiss German** spelling: `ss`, never `ß` (checked by a test). German and French address users
  formally (Sie, vous), Italian with Lei.

## What is translated

| Area                                | How                                                                                                                                                 |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| Web app texts, labels, toasts       | Message files                                                                                                                                       |
| Exports (CSV, Excel, printed PDF)   | Column headers and status values in the exporting user's language                                                                                   |
| Server errors                       | Server errors carry a code (`data._error`, or the field error's `code`); the web app shows `server.<code>` (or `server.fields.<field>.<code>`)      |
| PocketBase validation errors        | By their `validation_*` code                                                                                                                        |
| Score sheet problems                | By the scoring engine's issue code, with the criterion's label and limits                                                                           |
| Planner, schedule and health checks | By the server's issue/check codes                                                                                                                   |
| Emails                              | One editable template per notification **and** language; sent in the recipient's language ([M7 communication](M7-communication.md#templates-m7-02)) |

Unknown codes fall back to the server's English message, so a new server message is never lost,
only untranslated.

Not translated: content entered by users (event, category, team, round and block names, ruleset
labels and descriptions, review notes, snapshot titles), the ranking and scoring engines' validation
messages of the JSON configuration editors (admins only) and their formula explanations, technical
details (logs, error stacks), and CSV import column names (`team_name`, … stay as they are so files
work in every language).

## Recipient language of emails

`users.language` of the recipient's account: for team emails the account with the team's contact
email (`coach_email`). Without an account or a language: English. Templates
missing in a language fall back to the English template.
